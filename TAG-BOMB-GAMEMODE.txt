TAG / BOMB GAME MODE

What's new:
- The room is now a real match, not just free-roam.
- Once 2+ players are in the room, a 30-second queue countdown
  starts. Anyone who clicks JOIN PUBLIC can still get in during
  those 30 seconds. When the countdown hits 0 the roster locks and
  nobody else can join that match.
- A round-loading screen reveals roles: the chosen player sees
  "YOU HAVE THE BOMB", everyone else sees "GET READY TO RUN".
- When the loading screen ends, everyone else can move immediately,
  but the bomb holder is frozen for 5 more seconds before being
  released ("RELEASING IN Xs...").
- Once released, the bomb holder has 30 seconds to tag someone
  (walk close and press E). Each tag adds +3 seconds to the bomb
  timer and passes the bomb to the tagged player.
- If time runs out, the bomb holder is eliminated and sees
  "YOU HAVE BEEN BLOWN UP" with a RETURN TO LOBBY button. Every
  surviving player is immediately put into a new round with a new
  random bomb holder chosen from those still alive.
- This repeats until 1 player remains.
- In the final 1v1, the player who gets blown up instead sees a
  RETURN TO MAIN MENU button, and the survivor sees a "YOU WON!"
  screen with a RETURN TO LOBBY button.
- When the round begins, only the player who starts with the bomb is
  frozen — for 5 seconds — before being released. Everyone else can
  move immediately, no waiting.
- The bomb holder moves 2x as fast as everyone else while they have it.
- Timers are kept in sync across every device: instead of trusting
  each client's own clock, everyone recalibrates against whoever most
  recently sent a match update, and every round timestamp is chained
  off already-agreed values (the queue deadline, the previous bomb
  deadline) instead of "my own clock right now." That's also what
  fixed an earlier bug where two clients could occasionally disagree
  about who started with the bomb.
- The room now starts a match with as few as 2 players.
- A bouncing 💣 icon floats above whoever currently has the bomb, so
  everyone in the lobby can see who to run from (or chase).
- The title screen ("CAN'T CATCH ME" / PLAY button) has been removed.
  Clicking JOIN PUBLIC now drops you straight into the queue as soon
  as the room finishes loading.
- The CASTLE map has been removed, including from the map-select menu.
  In its place is a new TEMPLE map: a sandstone courtyard with corner
  towers, a domed central plaza, multiple staircases leading up to
  raised walkways and side buildings, and a glowing green pool near
  one edge — styled after the reference screenshot.

How it's synced (no game server):
- All of this rides on the same Supabase Realtime channel already
  used for movement. A new "match" broadcast event carries the full
  round state (phase, roster, alive players, bomb holder, timers).
- The player with the lowest connection id in the room acts as the
  "host" and is the only one who starts the queue countdown and
  locks in a new match's roster.
- Whoever currently holds the bomb is authoritative for tagging and
  for detonating (their own browser decides and broadcasts it),
  since they're the one with the freshest data about who's in reach.
- Every client just applies whichever match update it has last
  received, so everyone converges without needing a dedicated server.

Known limitations:
- Eliminated players can freely walk around the map again as soon as
  they dismiss the kill screen (there's no separate spectator camera).
- If the current bomb holder's browser closes at the exact instant
  the bomb should detonate, there's no server to force it, so that
  edge case isn't specifically handled.
- Tagging is proximity + an E press, not an animation/hit-reg system.
